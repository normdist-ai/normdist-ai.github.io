为什么同一个 div，在手机上能往上拖动？—— 移动端视口高度踩坑全记录

本文最后更新于 2026年8月5日 凌晨

翻车现场

一个 Next.js 的扫码页面，在电脑浏览器上看完美无缺——卡片撑满屏幕，底部贴着 iPhone 的横条 home 指示线。

切到手机上一看：卡片比屏幕高出了几十像素。没有出现滚动条，但手指从下往上拖，页面会「回弹」回去。就像……它被什么东西往外推了一点点。

同一个 div，同一套 CSS，PC 上完美、手机上超出边界。

直觉告诉我：肯定是个和视口相关的单位问题。但哪个单位？

排查过程

第一轮：以为是 height: 100% 没撑满

扫码卡片用的是 h-full，父容器用 flex-1，一层层往上追——父容器有 h-full，再往上也有，看起来没问题。

实际上问题恰恰相反：不是撑不满，是撑太满了。

第二轮：加 max-h 限制

我给卡片加了 max-h-[calc(100vh - 8rem)]，想把它卡死在视口以内。结果两边扫码页面对比起来高度还是不一样——一个撑得高，一个撑得矮。

原来 100vh 在不同层级上算出来的「视口」不一样。页面层级用了 max-w-4xl mx-auto 居中，这一层没加 h-full，高度链就断了。

第三轮：h-screen 反而越描越黑

我在 <main> 上加了 h-screen 想把高度锁死。结果超出更严重了——h-screen 等于 100vh，加上 flex 的 flex-1 一起作用，flex-1 想撑满父容器，h-screen 又想撑满整个视口，两个约束打架，页面直接超出。

关键教训：在 flex 布局里混用 flex-1 和 h-screen 等价于让浏览器做一道解不开的方程题。

第四轮：终于找到根因 —— 100vh 在手机上不是 100vh

把 h-screen 清掉后，超出问题小了很多，但还是有。手机页面还是能往上拖动。

问题出在最底层的 body 上。代码里写的是 h-screen，也就是 height: 100vh。

100vh 在移动端，永远是手机物理屏幕的高度，包含地址栏、导航栏、工具栏。

当手机浏览器的地址栏折叠后，实际能显示内容的区域（可见视口）比 100vh 小了一截——大约 56px（地址栏高度）+ 56px（底部导航）= 100px 左右。

所以 body 高度 = 100vh（物理屏幕），但 flex 容器分给 <main> 的高度是按 body 减去 header 算的，结果 <main> 里的内容比实际可视区域大了一截。没有滚动条（因为浏览器认为内容没有超出「视口」），但手指能拖动（浏览器允许 overscroll）。

最终方案

CSS 里有一个专门为移动端浏览器设计的单位：dvh（Dynamic Viewport Height）。

单位 含义 移动端行为
100vh 物理视口 永远 = 手机物理屏幕高度，含地址栏
100svh 最小视口 地址栏展开时的最小可视区
100dvh 动态视口 随地址栏折叠/展开动态变化

把 body 的 h-screen（100vh）换成 h-dvh（100dvh），地址栏折叠时 100dvh 自动缩小，完美贴合实际可视区域。

同时确保整个高度链干净——只用 flex 撑高，不要用 h-screen/h-full 硬约束：

高度链：body(h-dvh) → flex-1 → main(flex-1) → wrapper(h-full) → card(h-full)，层层传递，没有断裂，没有冲突。

验证

部署到生产环境后，手机刷新页面，四个扫码页面（扫码入库、扫码出库、扫码收货、扫码发货）卡片高度完全一致，刚好贴合屏幕，手指无法拖动，无滚动条。

踩坑记录

坑一：flex-1 和 h-screen 混用

现象：加了 h-full 后页面还是超出视口。

根因：flex-1 想撑满 flex 父容器，h-screen 又想撑满视口，两个约束同时生效时浏览器按 h-screen 走，超出 flex 容器。

解法：flex 布局下只用 flex-1 或 h-full，不要用 h-screen。

坑二：外层包裹层没有 flex 属性

现象：扫码卡片明明写了 h-full，但高度就是比另一个页面矮。

根因：扫码入口页用了 max-w-4xl mx-auto 包裹卡片，这一层没有 flex flex-col，里面的 h-full 找不到参照物，退化为 auto。

解法：包裹层加 flex flex-col h-full，让子元素的 h-full 生效。

坑三：多层 CSS 类叠加时高度链断裂

现象：每个文件单独看都写了 h-full，但页面就是不撑满。

根因：中间某个父容器没有 height: 100%（或等价的 flex 撑高），高度链在这一层断开了。

解法：从 <body> 到目标元素，一层一层往上追。任何一层断了，下面的 h-full 都白写。

坑四：浏览器缓存导致「改了没用」

现象：build 成功了，CSS 里也编译了新规则，但手机上看还是旧的样式。

根因：移动端浏览器缓存了旧版 CSS/JS 文件。

解法：地址栏加 ?v=999 清缓存，或手动清除浏览器缓存。

总结

移动端响应式的「高度」问题，本质上是视口单位选择和flex 高度链完整性两个问题的叠加。

记住一条原则：在 flex 布局里做高度，用 flex-1 撑高，用 h-dvh 定总高，不要用 h-screen（100vh）硬约束。
